# Sprint 2 (make switching irresistible) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shop moving from a notebook, Excel or another app is set up in ten minutes, finds the paperwork and the
figures it was missing, and Qistas is ready for its Google Play production launch.

**Architecture:** As in Sprint 1. Each item is a Laravel action with `/api/v1` endpoints (OpenAPI drift-tested), a web
page under `/app` for the computer, and Flutter screens. Everything sits behind an admin feature switch; new features
ship *off* and the owner turns them on in `/admin/features`. Money keeps its rules: bcmath strings, `decimal(18,4)`,
ledger rows never edited, corrections made by reversal. Every migration is run on PostgreSQL (PGlite) before it is
pushed.

**Tech Stack:** Laravel 13, Pest, Pint, Larastan 6; Flutter (Riverpod, go_router, dio); Supabase Postgres; mPDF; PHP
intl (Umm al-Qura calendar); GitHub Actions.

**Spec:** `docs/features/win-plan.html` (6.3 K4, K5, K8, K9; 6.8 Sprint 2; gap rows CT20–CT23, CT26, CT27, RP10,
RP11, RP14, RP15, RP17, CM07, CM10, PL02). The owner said "go ahead with Sprint 2" on 11 Oct 2026, after Sprint 1
shipped.

## Decisions (defaults the owner can change)

| # | Question | Decision |
|---|---|---|
| D1 | Late fees: where they live | A late fee is its own ledger line, never added to an instalment: table `late_fees` (contract, instalment, period number, amount, paid, status open, paid or waived; for charity or not). The workspace sets a policy, which is copied into each contract when it is made (`contracts.late_fee_policy` json), so a later change never alters an old deal. |
| D2 | Late fees: the policy | Fixed amount or a percent of what is still owed on the instalment; charged once, daily, weekly or monthly; starts after the contract's grace days (the existing `grace_until`); a cap per instalment and a cap per contract; optionally "to charity" (kept apart from the shop's income in every report). One nightly job adds each fee exactly once (unique instalment and period). |
| D3 | Late fees: paying them | A payment pays what is late first (instalments already due, oldest first), then open fees (oldest first), then instalments not yet due. Fee allocations have their own table, so a void puts them back exactly. Fees are the shop's income, or charity; they are never split with investors. A waiver needs a reason and is audited. |
| D4 | Hijri dates | Umm al-Qura, from PHP intl (`ar@calendar=islamic-umalqura`, in the image and locally) and the Dart `hijri` package. Shown beside the Gregorian date wherever the workspace turns it on (a workspace tool setting: off, beside, Hijri first); dates can be typed or picked in Hijri in the app and the web forms. Stored dates stay Gregorian. |
| D5 | Contract photos and the promissory note | Vercel's file disk is not permanent (no `FILESYSTEM_DISK`), so contract photos are kept in the database like transfer receipts: redrawn without location data, at most 1600 px, a few hundred KB each, and served through short-lived signed routes. When the owner adds object storage (S3 or Supabase Storage), they move there behind the same `Files` interface. Guarantor ID numbers are encrypted at rest and shown masked; collectors never see them. The contract and promissory-note PDFs carry the existing verification QR. **The promissory note's wording is a draft until the owner's lawyer approves it**: the switch stays off until then. |
| D6 | Signature | On the owner's screen (the existing signature pad), or through a link with a one-time code sent to the customer's phone (the customer signs on their own phone; the link expires in 24 hours and works once). |
| D7 | Charts and profit | One reports page on the web and one screen in the app: a cash-flow forecast for 30, 60 and 90 days (labelled "expected"), ageing buckets (current, 1–30, 31–60, 61–90, 90+), the collection rate, and profit as money comes in, by month, investor and product (the investor ledger's rule). Charts are drawn by the server as SVG on the web and by Flutter's canvas in the app (no chart library), and every table exports to Excel. |
| D8 | Import | Excel and CSV first (openspout is already in place): columns recognised in five languages, a trial run that shows every row and every problem, then one confirm. Old balances become opening lines (an open contract with an opening charge, or a scheduled contract with its paid part as a payment dated on the import day). AI reading of notebook photos and other apps' PDF reports uses the Claude API (`claude-sonnet-5-5`) with the owner's key, saved encrypted in the platform settings. Every row goes to the same review screen, and nothing is saved until the owner confirms. Until the key exists, only Excel and CSV are offered. |
| D9 | Receipt printers | The roll-size receipt (58 and 80 mm, built in Sprint 1) is sent to Android's print service from the app (`printing` package), which reaches the thermal printers whose apps register with it. No printer-specific Bluetooth code. |
| D10 | Language paths and the status page | Public pages also answer at `/ar/…`, `/fr/…`, `/es/…`, `/ur/…`, with hreflang pointing at those paths; `?lang=` keeps working. Switching pages: "from a notebook", "from Excel", "from another app". A public `/status` page shows the last health check and the scheduler. The own domain waits for the owner. |
| D11 | Play production launch | Listing text from the Win Plan (6.7) in five languages, and phone screenshots rendered from the app's visual tests in five languages at Play's sizes, kept in `docs/store/`. The trailer is filmed by the owner after this sprint, from real app screens. |
| D12 | iPhone | Needs the owner's Apple developer account. This sprint prepares what does not need it (bundle id, permission strings, an iOS CI job that runs when the signing secrets exist); TestFlight follows the account. |

## Global Constraints

- Tenancy: tenant-owned models use `BelongsToTenant`; another workspace's record is a 404.
- Money: never float; `App\Support\Money`; Dart `Money` (BigInt cents).
- Every new feature declares its label, description, group, off behaviour and defaults; the catalogue test stays green.
- Every user-visible string in five languages (web `scripts/merge_translations.py`, app `tool/i18n.py`; app-only strings
  never go into the web lang files); Arabic wording is count-neutral.
- `docs/api/openapi.yaml` is updated with each endpoint (the drift test); PUT, never PATCH.
- Gates before each commit: web `php vendor/bin/pest --parallel`, `pint --dirty`, `phpstan analyse`; app `flutter
  analyze` (zero issues) and `flutter test`; never `dart format`. Each new migration is run on PGlite.
- Each task: tests first, a mutation pass on its rules, commit, push through the terminal tool, check the deploy.
- The app's version goes up with each task that changes the app.

## Review Focus

1. **A payment on a contract with late fees, then voided:** the instalments and the fees go back exactly as they were,
   and the statement balances.
2. **The nightly fee job run twice, or after days missed:** each instalment gets each period's fee once, never past
   the caps, and never for days within the grace.
3. **A late-fee policy changed after contracts exist:** old contracts keep the policy they were made with.
4. **An import with bad rows** (a missing name, an amount in words, an unknown phone format, a duplicate): the trial
   run names the row and the column, and nothing is saved until the owner confirms.
5. **Hijri dates near the end of a month and across a year boundary:** shown and parsed the same on the web, in the
   app and in PDFs.
