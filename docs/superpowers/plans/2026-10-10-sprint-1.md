# Sprint 1 (parity and the first three killers) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nobody who compares Qistas with Installment & Accounting Pro can find a must-have Qistas lacks, and Qistas already shows three things that app cannot follow: every device on one ledger (K1), reminders that do the work (K2, part 1) and terms that bend (K3).

**Architecture:** Every item is a Laravel action plus API endpoints (`/api/v1`, OpenAPI drift-tested), a web-app page under `/app` where the owner works on a computer, and Flutter screens, all behind an admin feature switch from the existing Feature Control (new features ship *off*; the owner turns them on in `/admin/features`). Money keeps its rules: bcmath strings, `decimal(18,4)`, ledger rows never edited, corrections are reversals.

**Tech Stack:** Laravel 13, Pest, Pint, Larastan 6; Flutter (Riverpod, go_router, dio); Supabase Postgres; mPDF; GitHub Actions.

**Spec:** `docs/features/win-plan.html` (sections 6.1, 6.2 PP1–PP17, 6.3 K1–K3, 6.8 Sprint 1), owner's go-ahead of 10 Oct 2026. Background: `docs/features/QISTAS_FEATURES_BRIEF.md`.

## Global Constraints

- Tenancy: tenant-owned models use `BelongsToTenant`; another workspace's record is a 404.
- Money: never float; `App\Support\Money`; Dart `Money` (BigInt cents).
- Every feature declares label, description, group, offBehaviour, defaults; catalogue-integrity test stays green.
- Every user-visible string in five languages (web `scripts/merge_translations.py`, app `tool/i18n.py`; the Dart translations test is the gate).
- `docs/api/openapi.yaml` updated with each endpoint (drift test).
- Gates before each commit: web `php vendor/bin/pest`, `vendor/bin/pint --dirty`, `vendor/bin/phpstan analyse`; app `flutter analyze` (zero issues), `flutter test`. Never run `dart format`.
- Each task: tests first, mutation-check its key rule, commit, push through the terminal tool, then the next task.
- New tables get row-level security (`qistas:secure-database` covers them; its test lists every table).

## Review Focus

1. **Plan limits after a downgrade** — a Pro workspace with 3 members and 4 investors drops to Free: nothing is removed, adding is refused with the plan message.
2. **Payments on contracts funded by an investor and later reversed** — the investor's wallet and profit go back exactly; a reversal of a reversal is impossible.
3. **Custom schedules that do not add up, or dates out of order** — refused with a message on the row at fault, on web and app.
4. **Account deletion mid-way** — a workspace in its 30 days is read-only everywhere (web, API, app) and restorable; the purge never touches another workspace.
5. **Feature switched off while data exists** — investors, open contracts, tags and alerts stay readable; new actions are refused with `feature_unavailable`.
